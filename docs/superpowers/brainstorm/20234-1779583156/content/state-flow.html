Status pill state machine — current (as-shipped)

Two parallel flows (Selling and Buying) with branches, terminal states, and inconsistencies. Below the flows, I pitch four consolidation options.

Selling — state machine (8 labels)
User creates listing, saves as draft
Draft
User publishes; no orders yet
Live
Buyer(s) place orders → seller has offers waiting
3 pending
Seller accepts an order → pickup time scheduled
Pickup in 2h 14m
Pickup time passes → seller has not yet confirmed
Pickup ready
Seller confirms pickup happened (rated buyer); waiting for buyer
Awaiting buyer
Both parties confirmed pickup → terminal positive
Completed
Alternative terminals from Live:
Sold — listing manually marked sold
Expired — listing time ran out, no pickup
Confirmed — likely DEAD CODE post-PR #12 ("Pickup in {label}" replaced this)
Buying — state machine (9 labels)
Buyer places order on a Live listing
Pending
Seller accepts → pickup time scheduled
Pickup in 2h 14m
Pickup time passes → buyer has not yet confirmed
Pickup ready
Buyer confirms pickup happened (rated seller); waiting for seller
Awaiting seller
Both parties confirmed → terminal positive
Completed
Alternative terminals (each ends the flow):
Declined — seller declined
Withdrawn — buyer withdrew
Expired — seller didn't respond in time
Cancelled by seller — seller cancelled post-confirmation
Inconsistency: Selling compact table uses 8 labels; the Selling Listings tab card grid uses only 5 (Live / Sold / Draft / Expired / Completed) and pushes order state into inner buttons. Same listing renders different status text on the two surfaces. Worth flattening or aligning.
Color mismatch: "Awaiting buyer" (Selling) uses jade (bg-primary); "Awaiting seller" (Buying) uses amber (bg-warning/10). These are symmetric mirror states — same wait pattern, different colors. Either both should be amber (action needed by the other party = mildly tense) or both jade (still in happy path).

Consolidation pitches

Pick whichever combination resonates — or describe a different direction.

A

Minimal cleanup — fix inconsistencies, drop dead code (Recommended)

What changes
  • Remove the dead "Confirmed" branch from Selling (PR #12 made it unreachable).
  • Align Selling card-grid statusLabel with the compact-table version — same listing, same pill on both surfaces.
  • Recolor "Awaiting buyer" and "Awaiting seller" consistently — both amber (waiting on the other party, mild urgency).
Pitch
Keeps all current labels; just fixes inconsistencies and dead code. Lowest risk, highest "bang per buck." No user-facing copy changes — purely tightening.
B

Merge mirror "Awaiting" states + simplify terminal failures

What changes
  • Replace "Awaiting buyer" and "Awaiting seller" with a single "Awaiting confirmation" label (amber). Reduces vocabulary by 1, generic enough for both sides.
  • Replace "Declined" / "Withdrawn" / "Expired" / "Cancelled by seller" with a single "Cancelled" label (muted grey) — collapse 4 terminal-failure states into one. The detail (who cancelled / why) moves into the order summary modal, not the pill.
  • Plus everything in A.
Pitch
Trades off granularity for clarity. Some users might want to know "did the seller decline or did I withdraw?" — but that's typically apparent from context (was there a seller response?) and the order summary modal shows the full story.
Final pill count
Selling: 7 (was 8). Buying: 6 (was 9). Total unique labels: ~10 (was ~15).
C

Three-color system: in-progress / action-needed / done

What changes
  • Strict color semantics: jade = "in motion, no action needed from you"; amber = "you have an action to take"; muted = "done / cancelled / inactive".
  • Recolor: "Pickup ready" → amber (you need to confirm). "{N} pending" → amber (you need to review). "Pickup in {label}" → jade (in motion, no action). Other labels stay where they semantically belong.
  • Plus everything in A + B.
Pitch
User can scan vertically and immediately see "what needs my attention" (amber) vs "what's progressing" (jade) vs "what's done" (muted). Strongest information design.
D

Radical — collapse to 5 universal labels, role-disambiguated by table

What changes
  • Single shared vocabulary across Selling + Buying: Active · Pending · Scheduled · Action needed · Closed.
  • "Active" = Live / Draft (with subtle visual variants for draft).
  • "Pending" = unresolved offer (Selling: {N} pending; Buying: your placed order is pending).
  • "Scheduled" = confirmed time + countdown (Selling + Buying).
  • "Action needed" = pickup ready or awaiting your review.
  • "Closed" = completed / declined / withdrawn / expired / cancelled / sold.
  • Detail accessible via row click → order/listing summary modal.
Pitch
Maximum simplification. Trades label specificity for table-level scannability. Risky — power users (heavy sellers) may want the granularity back. Best if Cosello explicitly wants "Slack-tier simple" status display.

Pick A / B / C / D — multi-select is fine if pieces of different pitches resonate.
