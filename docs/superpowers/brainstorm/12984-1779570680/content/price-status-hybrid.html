Price / Status column hybrids

"Old" = column-locked (Status edge same across rows, pills sit inside fixed slot). "New" = content-width (pills wrap to text, column edges shift). Hybrids combine pieces of both.

A

Status column locked, Price content-width (Recommended)

Price is content-width (no min-width — short prices like "$48" don't waste space). Status column gets a min-width so pill LEFT edges align across rows. Best of both: clean price column, locked status alignment.

B

Both locked, BUT smaller min-widths

Both Price and Status have min-widths, but tighter than the original (48px / 96px instead of 56px / 108px). Pills still don't share an x-edge if content varies wildly, but for typical content the columns mostly line up. Slight visual breathing room without the over-padded feel.

C

Status pill right-aligned in a locked column

Status column gets min-width 108px AND the pill inside is right-aligned (so the pill's RIGHT edge sits flush with the table's right edge, regardless of pill length). Price is content-width. Different alignment philosophy: pill anchors to the right not the left.

D

Price locked, Status content-width (inverse of A)

Price gets min-width (so the price column aligns across rows — useful for scanning prices vertically). Status pill is content-width and floats. Less typical, but if scanning prices is more important than scanning status, this is the right shape.
